# 中文姓名生成 Agent

**以确定性规则、本地检索和有界多 Agent 探索，渐进改造传统取名系统。**

[English](README.md) · [简体中文](README.zh-CN.md)

## 项目概览

这是供专业取名员工使用的内部辅助工具，将家庭期望转化为个性化中文姓名推荐。原有规则引擎能够稳定执行取名约束，但无法理解开放式愿望，也不能判断完整姓名是否自然。V2 保留确定性规则边界，引入检索、专业探索路线与独立 LLM 评审，最终仍由人工判断。

## 工程亮点

- **多策略检索：**BM25 与本地 BGE 单字向量组合检索覆盖完整合法姓名空间；可用的双字组合提示与已核实文本证据补充检索信号，通过倒数排名融合（RRF）形成有界的 LLM 候选窗口。
- **有界多 Agent 执行：**四条路线共享只读家庭上下文与候选池身份，以线程并发、加锁预算预留、稳定合并顺序与单路失败隔离约束执行。
- **合法性、质量与证据分离：**P2 校验候选 ID，来源盲态 P4 评价完整姓名；代码分别处理硬淘汰、排序降权与解释材料的声明限制。
- **预算约束下的选择：**阶段预算、版本化缓存和最多一次定向补充限制探索；最终兼顾质量与多样性，不为各路线设置固定入选比例。
- **可恢复的结果交付：**持久事件驱动 SSE 进度展示；解释生成前先保存推荐检查点，解释失败时可保留有效推荐，并明确标记部分完成。

## V2 系统架构

![V2 system architecture](<assets/High-Level Architecture.png>)

确定性引擎建立合法候选池，适用的探索路线通过本地检索发现候选，再进入独立整名评审与组合选择；推荐结果先于解释生成保存。检索分只引导发现，不能替代完整姓名的质量判断。

| 路线 | 职责与证据边界 |
| --- | --- |
| Poetry／诗词 | 检索本地语料，区分连续原文证据与一般意象支持；字面命中本身不代表适合用作取名出处。 |
| Regional／地域 | 基于实际填写的出生地、家乡或家庭背景探索，不混淆字段；未核实联想只作为明确标记的意象。 |
| Time／时间 | 从实际日期、时间探索自然时间意象；具体事件必须有相应证据。 |
| Creative／创意 | 在合法池内探索自然、现代且意境连贯的完整姓名，创意解释不能升级为历史事实。 |

独立专业初评模块已实现，但**当前 Preview 跳过付费的逐候选专业初评，将质量预算留给统一 P4**，因此上图未将该可选阶段画入主流程。P4 不读取检索分或路线叙事；随后组合分配器选择最多 30 个名字，质量或预算不足时允许更少。P5 提供简短解释与按需深读，区分通过校验的事实证据与创意意象。

## 架构演进：V1 → V2

| 设计问题 | V1 | V2 |
| --- | --- | --- |
| 候选发现 | 单服务协调语义、文化、浏览与创意工具 | 四条可独立执行的路线，共享上下文并明确启用条件 |
| 检索策略 | BM25 与组合语义列表交错返回 | 全池多策略排序、RRF 融合与有界候选窗口 |
| 推荐选择 | 独立整名评审与多样性筛选 | 统一来源盲态评审、独立声明限制与动态组合分配 |
| 恢复机制 | 工作流预算、缓存与会话持久化 | 路线隔离、阶段检查点、持久事件及 P5 失败后的推荐保留 |
| 渐进迁移 | 已有默认工作流 | 独立 V2 Preview 与存储，V1 保持默认入口 |

早期设想为每个姓名组合预生成 LLM 释义，后来改为复用单字语义资产，仅对有界候选进行完整姓名评估。单字语义组合始终只是检索线索，不是经过核实的整名释义。

## 技术栈

| 层次 | 私有实现实际使用的技术 |
| --- | --- |
| 界面 | Next.js、React、TypeScript、Tailwind CSS |

## 评测与可靠性

**截至 2026 年 10 月 28 日：**V2 契约、四路探索、编排、统一 P4／组合选择及 Preview／P5 均已实现。历史 D-1、D-2 离线报告记录了 Python 回归、Web 测试、类型检查和构建通过；这些结论只对应当时快照，后续检索、并发与韧性修复仍需统一最终验收。

黄金基准回归保护原有规则行为，当前测试源码还覆盖准入、有界并发、预算预留、缓存作用域、部分失败及检查点／结果恢复。付费请求结果未知时，Journal 阻止自动重发；会话可恢复不意味着任意中断任务都能安全续跑。

**真实取名质量仍待验收。**V1、增强单 Agent 与 V2 的同预算对照尚未完成最终验收，不宣称已取得可量化的效率提升、质量优势或生产吞吐指标。

路线并发发生在同一次取名任务内，Preview 一次只接收一个活动任务。多用户隔离、共享数据库／缓存基础设施、可靠队列 Worker 与水平扩容仍属于后续规划。

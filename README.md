# Chinese Name Generator — AI-Assisted Legacy Modernization

A modern Chinese naming web application rebuilt from a legacy Python prototype through an AI-assisted development workflow.

Next.js · React · TypeScript · Tailwind CSS · Gemini API · Vitest

## Overview

This project extends a legacy naming workflow from a traditional-culture application scenario into a maintainable modern web application. The original Python/Streamlit prototype implemented a traditional Chinese naming process; using Claude Code in an AI-assisted / Vibe Coding workflow, I migrated it to a full-stack Next.js application — while preserving the original business rules instead of letting the AI rewrite them.

The application guides users through a structured flow: basic information → naming conditions → candidate generation → name selection → a short Chinese explanation of the chosen name, generated by Google Gemini.

## What I Built

- Migrated a legacy Python/Streamlit application to Next.js + TypeScript.
- Separated UI, API routes, validation, data loading, and naming logic into distinct layers.
- Preserved legacy business behavior through 126 Golden Test cases generated from the original Python code.
- Built a structured naming workflow: candidate generation, grouped browsing, and name selection.
- Added parent-name avoidance rules at the data-merging layer without touching the validated core engine.
- Integrated the Google Gemini API for contextual Chinese name explanations through a dedicated `/api/explain` route.
- Managed API credentials through server-side environment variables only.

## Vibe Coding Workflow

```
Legacy Python Prototype
        ↓
Claude Code–Assisted Analysis
        ↓
Next.js / TypeScript Migration
        ↓
Golden Test Validation
        ↓
UI / Product Iteration
        ↓
Regression Testing
        ↓
Gemini API Integration
```

The point was never to let an AI generate code from scratch and ship it. Instead, the workflow was:

- Use Claude Code to read and understand the legacy codebase.
- Define explicit architecture and protected-core constraints before any refactoring.
- Use Golden Tests to prove the migration preserved the original behavior.
- When a regression appeared, track it down through controlled API comparison and lock the fix with regression tests.

One real example: after adding automatic parent-name avoidance, every candidate name was filtered out (0 results). Controlled API comparisons isolated the cause — the automatically added character (the father's surname) matched the baby's surname, so it matched every candidate. The fix was made in the outer merging layer, leaving the core naming engine untouched.

## Getting Started

```bash
npm install
npm run dev     # http://localhost:3000
npm test        # 178 tests, including 126 Golden cases
npm run build   # production build
```

For the name-explanation feature, create `.env.local` with `GEMINI_API_KEY=<your-key>` (never committed). Name generation itself has no external dependencies — all naming data ships as local CSV files.
